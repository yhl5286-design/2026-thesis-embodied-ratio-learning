# 악기 제작실 (Spec D) — 설계 스펙

- **작성일**: 2026-05-20 (모바일 테스트 피드백 반영 개정)
- **대상 파일**: `index.html` (단일 HTML 프로토타입)
- **범위**: `instrument` 탭의 **거문고 재설계만** — 길이에 따른 연속 음높이 + 안족 드래그(모바일 친화) + 햅틱 + 길이/비 토글. (팬플룻은 변경 없음. 소리 탐험실 슬라이더 개선은 후속 별도.)
- **선행**: Spec 1·C 병합 완료 — `Logger`, blind 토글 패턴 재사용
- **상위 맥락**: [[project_logging_redesign]], reverse scaffolding([[project_design_direction]])

## 1. 목적

거문고를 **안족을 움직여 현의 울리는 길이를 바꾸면 음높이가 연속적으로 변하는** 악기로 다듬는다. 모바일 터치에서 조작이 쉽도록 안족 잡는 영역을 키우고, 누르는 촉각(햅틱)·현 진동 시각효과를 더한다. 현 길이는 기본 숨기되 **토글로 비(ratio)를 정량화**해 색상·화음의 2:3과 잇는다.

## 2. 현재 상태 (출발점)

- `instrument` 탭에 팬플룻(`inst-panflute`)과 거문고(`inst-string`). `initInst()`가 둘 다 초기화.
- 거문고: `strCanvas`(640×200). `strLenA`(현 길이, `STR_MIN=28`~`STR_MAX=68`), `strFreqFromLen(l)=STR_REF/l`(`STR_REF=60*262`) — **음높이는 이미 길이에 연속**. 안족(빨강 삼각형)을 드래그(`strInitCanvas`의 pointer 핸들러; 히트테스트 `|mx-anjokAX|<18 && |my-strAY|<22`)해 길이 변경. **"현 길이: Xcm" 텍스트 노출**. 바닥에 `XYLO_FREQS` 음 위치 눈금. `strShowNote`가 `nearestNote`로 가장 가까운 음 이름을 표시.
- 모바일 피드백: 안족 잡기/조작이 어렵다(히트영역이 작음). 음 이름 스냅 표시 때문에 "정확히 안 맞춰도 그 음" 인상 → 길이대로 연속 변화를 분명히 하고 싶음.

## 3. 결정 사항 (합의됨)

| 항목 | 결정 |
|---|---|
| 음높이 | **길이에 따라 연속 변화**(글리산도). 이산 음 스냅·고정 괘 방식 폐기 |
| 조작 | **안족 드래그**, 잡는 **히트영역 크게**(모바일 친화) |
| 참고 눈금 | 도·레·미·솔·라 위치를 **흐린 가이드**로(스냅 없음, 방향 잡기용) |
| 누름 촉각 | 안족 잡는 순간 **`navigator.vibrate(20)`**(지원 기기만) + 현 진동 시각효과 |
| 길이 표시 | 기본 **숨김**, **비율 보기 토글**로 길이(cm)+도 대비 비 실시간 노출 |
| 팬플룻 | **변경 없음**(사운드 그대로) |
| 소리 탐험실 슬라이더 | **이번 범위 밖**(후속 별도) |
| 로깅 | 거문고 = `geomungo.play` open trial(드래그 멈춤 시 상태 기록) + blind_toggle |

## 4. 거문고 재설계

### 4.1 연속 길이→음높이
- 안족을 현 위에서 드래그 → 울리는 길이(나비 nutX → 안족 anjokAX)가 연속 변하고, `strFreqFromLen(strLenA)`로 음높이가 **부드럽게 연속 변화**. 드래그 중 음이 글리산도처럼 따라옴(현행 `stringNote` 짧은 재생 유지, 단 음 이름 스냅 강조는 약화).
- `nearestNote` 기반 음 이름 표시는 **참고용으로만**(작게/흐리게), 음높이 자체는 스냅하지 않음.

### 4.2 모바일 친화 안족 드래그
- 안족 잡기 히트영역을 크게: 현 활성 구간(나비~안족 부근) 세로로 넓은 띠(예: `|my-strAY|<H*0.4`)와 안족 주변 가로 여유(예: `|mx-anjokAX|<32`)로 확대. 또는 **활성 현 어디를 잡아도** 안족 드래그 시작.
- 안족 시각을 더 크고 또렷하게(잡을 수 있는 손잡이 느낌). `touch-action:none` 유지(현재 적용됨).
- `setPointerCapture`로 드래그 연속성 보장(현행 유지).

### 4.3 누름 촉각 + 현 진동
- **햅틱**: 안족 pointerdown(잡는 순간) `if(navigator.vibrate)navigator.vibrate(20);` — 미지원(iPad/데스크톱) 자동 무시, 앱 정상. progressive enhancement.
- **현 진동 시각효과**: 드래그 갱신/재생 시 울리는 구간을 짧게 떨리게(사인 형태 2~3회, requestAnimationFrame ~300ms 후 직선 복귀). 캔버스 redraw에 진동 위상 반영.

### 4.4 길이/비 — 기본 숨김 + 비율 보기 토글
- 기본: 캔버스의 "현 길이: Xcm" 텍스트 비표시(지시 "길이만 보이지 않고").
- **비율 보기 토글**(거문고 영역 우상단, `*-mode-toggle` 패턴): 켜면
  - 현재 울리는 **길이(cm)** 실시간 표시.
  - **도 대비 비**: (현재 길이) : (도 기준 길이 60cm)를 기약비로 실시간. 예) 솔 위치(≈40cm) → "약 2 : 3"(색상·화음의 2:3과 동일 — 전이 단서). 연속이라 근사 비로 표기(가까운 정수비 또는 소수+근사 기약비).
- 토글 상태 변화 → `Logger.event('blind_toggle',{tab:'instrument',inst:'geomungo',blind})`.

### 4.5 비례 학습 위치
- 자유 연주·감각 중심, 비 토글로 길이 비 발견(reverse scaffolding). 정량 심화는 화음 감상실 담당. 현 길이가 음높이와 역비례임을 토글로 드러냄.

## 5. 팬플룻
- **변경 없음.** 사운드(`pfNote`)·제작 과제 그대로. (사용자: "소리는 괜찮다".)

## 6. 로깅 (microgenetic)
- 거문고 화면 활성(`instSet('string')`) 시 `geomungoTrial = Logger.startTrial({tab:'instrument',activity:'geomungo.play',task:'play'})`(중복 가드).
- 드래그가 멈춰 머문 길이마다 `Logger.trialState(geomungoTrial,{lenCm:+strLenA.toFixed(1), freq:Math.round(strFreqFromLen(strLenA)), ratioToDo:approxRatio})` (400ms debounce는 Logger 내장).
- 팬플룻 전환·탭 이탈 시 `Logger.endTrial(geomungoTrial,{outcome:'open',finalState:{lenCm,freq}})`.
- 비율 보기 토글 → blind_toggle 이벤트.

## 7. 데이터 구조 영향
- 새 `activityId`: `geomungo.play`, `taskId`: `play`. events 신규 값 없음(blind_toggle 기존). 시트 스키마 변화 없음.

## 8. 검증 방침
- 인라인 스크립트 `node --check` + Playwright 브라우저 검증.
- 핵심 체크: (a) 안족 드래그로 음높이 연속 변화(글리산도), (b) 히트영역 확대(여유 좌표에서 잡힘), (c) 길이 cm 기본 숨김·비율 토글로 길이+비(솔≈2:3) 노출, (d) 햅틱 호출 시 에러 0(미지원 기기), (e) 현 진동 시각효과 동작, (f) `geomungo.play` trial에 길이 trajectory 적재, (g) 팬플룻·다른 탭 회귀 0.
- 실제 햅틱 진동은 안드로이드 태블릿 실기 확인(사용자). Playwright/데스크톱에선 호출 무에러까지만.
