# 소리 탐험실 (Spec C) — 설계 스펙

- **작성일**: 2026-05-20
- **대상 파일**: `index.html` (단일 HTML 프로토타입)
- **범위**: `sound` 탭(소리 탐험실)을 순차 2단계로 재구성 — (1) 물의 양으로 소리 변화 느끼기 → (2) 물의 양으로 도레미파솔라시도(8음) 만들기
- **선행**: Spec 1(로깅 인프라) 병합 완료 — `Logger.startTrial/trialState/endTrial/event` 재사용
- **상위 맥락**: [[project_logging_redesign]], reverse scaffolding 방향([[project_design_direction]])

## 1. 목적

학습자가 물의 양을 바꾸며 소리(음높이)가 어떻게 변하는지 **귀로 먼저 감각**하고, 이어서 물의 양을 맞춰 **도레미파솔라시도 8음 음계를 직접 완성**한다. 이 탭은 **감각·튜닝 활동**에 집중하며, 비(ratio) 개념의 정량 학습은 화음 감상실이 담당한다(물의 양↔주파수 비를 인코딩하지 않음 — 사용자 결정).

## 2. 현재 상태 (출발점)

- `sound` 탭(`#lab-sound`)에 `sndS1` 한 블록이 있고 그 안에 두 활동이 **나란히 동시 표시**됨:
  - **소리 탐험**: 유리컵 1개 + 슬라이더(`glBuildS1`/`glS1Move`), `glFreq(h)`로 물높이→음높이(물↑→음↓), mL 표시, 12회 조작 후 안내.
  - **도레미 만들기**: 컵 3개(도·레·미, `glBuildDoremi`/`glDoremiSetCells`), 칸(셀) 클릭, 목표 칸수 `SCALE_CELLS[0..2]=[8,7,6]`.
- **죽은 코드**: 8음용 `glBuildS2`/`glS2SetCells`/`glS2PlayScale`/`glS2Reset` 및 미연결 DOM `gl2Row` — 호출처·DOM 모두 없음(옛 구조 잔재). `SCALE_NOTES`(8)·`SCALE_FREQ`(8)·`SCALE_CELLS`(8)는 유효.

## 3. 결정 사항 (합의됨)

| 항목 | 결정 |
|---|---|
| 활동 흐름 | **순차** — 1단계 탐험을 거친 뒤 2단계 만들기가 잠금 해제 |
| 물의 양↔비 | 튜닝 목표일 뿐, 비 무관 (비는 화음 감상실) |
| 1단계 감각 | **mL 숨김(blind)**, 우상단 토글로 표시 가능 (색상·화음과 동일 패턴) |
| 1단계 해제 조건 | 가벼움 — "골고루 들어보세요" 안내 + 저음역·고음역을 모두 들어보면 해제(관대) |
| 2단계 인터랙션 | **칸(셀) 클릭**, 3음 방식을 **8음으로 확장** |
| trial 단위 | 1단계=`sound.explore` open trial 1개 / 2단계=**음 하나당 1 trial**(`sound.scale`) |
| 코드 정리 | 죽은 `glBuildS2`/`glS2*`/`gl2Row` 제거, 8음 만들기는 단일 함수군으로 통합 |

## 4. 1단계 — 소리 탐험 (감각)

### 4.1 UI / 동작
- 유리컵 1개 + 슬라이더(현 `glBuildS1` 유지). 컵/미니버튼 탭 시 음 재생(`glPlayBrief`/`glPlayHold`).
- 물높이→음높이: 기존 `glFreq` 유지(물 많을수록 낮은 음).
- **mL 숨김**: 탐험 영역에 `snd-blind` 상태 클래스를 두고 mL 표기(`gl1P0`)를 `display:none`. 우상단 토글 버튼으로 켜고 끔(색상 `col-blind`/화음 `harm-blind` 패턴 차용).
- **안내 문구**: "물을 적게도, 많게도 — **골고루** 움직여 소리가 어떻게 달라지는지 들어보세요." (`gl1Desc`)

### 4.2 잠금 해제 조건 (가벼움)
- 슬라이더로 재생한 물높이의 **최저·최고를 추적**. 저음역(예: height ≤ 30)과 고음역(예: height ≥ 70)을 **각각 1회 이상** 들어보면 해제.
- 안전망: 위 조건 미충족이어도 **8회 이상 조작**하면 해제(막히지 않게).
- 해제 시 `gl1FB`에 격려 + 2단계 영역(현 `glReveal` 자리)을 표시/활성화.

### 4.3 2단계 표시 전환
- 1단계와 2단계는 **순차**이므로, 2단계 만들기 블록은 처음엔 가려져 있다가(`display:none` 또는 흐림+잠금 오버레이) 해제 시 나타난다.
- "처음부터" 버튼으로 1단계로 되돌아갈 수 있게 유지(탐험 재시도).

## 5. 2단계 — 도레미파솔라시도 만들기 (8음)

### 5.1 UI / 동작
- 컵 **8개**(`SCALE_NOTES=['도','레','미','파','솔','라','시','도↑']`), 각 컵 10칸.
- 칸 클릭 시 그 높이까지 물 채움(현 `glDoremiSetCells` 방식). 목표 칸수 `SCALE_CELLS=[8,7,6,5,4,3,2,1]`(도=물 많음·낮은 음 → 도↑=물 적음·높은 음, 1단계 감각과 일관).
- 채울 때마다 그 칸 수에 해당하는 음을 짧게 재생(맞으면 정확한 `SCALE_FREQ[i]`, 아니면 근접 음). 튜닝 피드백: `눌러서 채워요` / `↑ 더` / `↓ 줄여` / `✓ 도!`.
- 맞으면 컵 둘레 초록 발광(`tuned-unit`). 8개 모두 맞으면 **전체 연주** 버튼 활성화(저→고 순차 재생, 죽은 `glS2PlayScale` 로직 이식).
- mL 숨김: 만들기 단계에서도 mL 미표시 — 칸 수·음 라벨·튜닝 피드백만 노출(귀로 맞추게). (칸 수 자체는 조작 피드백이라 표시)

### 5.2 구현 통합
- **단일 8음 함수군**으로 통합한다. 현 살아있는 `glBuildDoremi`/`glDoremiSetCells`(3음, blind·wiring 검증됨)를 **8음으로 확장**(`DOREMI_LABELS`→`SCALE_NOTES`, 루프 3→8, 목표 `SCALE_CELLS[i]`)하고, **죽은 `glBuildS2`/`glS2SetCells`/`glS2CheckAll`/`glS2PlayScale`/`glS2Reset` 및 `gl2*` 잔재를 삭제**한다. 전체 연주만 죽은 코드에서 로직을 가져와 새 함수로 편입.
- `gl` 상태: `doremi`/`doremiTuned`(길이 3)를 8로 확장하거나 기존 `h2`/`tuned`(길이 8) 재사용 — 구현 시 하나로 정리(중복 상태 제거).

## 6. Reverse scaffolding (blind) 처리

- 탐험·만들기 모두 기본 **mL 숨김**. 우상단 토글(`소리:🔢 숫자 보기`)로 표시/숨김 전환.
- 토글 상태 변화는 `Logger.event('blind_toggle',{tab:'sound', blind})`로 기록.
- 칸 수·음 라벨·튜닝 피드백은 항상 표시(이건 "정답 수치"가 아니라 조작·청각 피드백).

## 7. 로깅 (microgenetic) 매핑

`Logger`(Spec 1) 재사용. 모든 호출은 동기·safe(앱 안정성 보장).

- **1단계 탐험** = open trial 1개
  - `sound` 탭 진입 & 1단계 시작 시 `startTrial({tab:'sound', activity:'sound.explore', task:'explore'})`.
  - 슬라이더가 새 높이에 머물 때 `trialState(id,{height, freq})`(400ms debounce 내장).
  - 2단계 잠금 해제(또는 탭 이탈) 시 `endTrial(id,{outcome:'open', finalState:{lowSeen, highSeen, count}})`.
- **2단계 만들기** = 음 하나당 1 trial
  - 어떤 컵이 미완성 상태에서 칸을 처음 조작하면 그 음의 trial 시작: `startTrial({tab:'sound', activity:'sound.scale', task:'note_'+노트id, attemptNo})`.
  - 칸 변경마다 `trialState(id,{cells, note})`.
  - 목표 칸수 명중 시 `endTrial(id,{outcome:'correct', finalState:{cells}})`. 명중 후 다시 바꾸면 새 attempt로 `attemptNo` 증가하여 재시작.
  - 8음 전부 완성 시 `Logger.event('scale_complete',{tab:'sound'})`.
- 음 id는 `도/레/미/파/솔/라/시/도↑` → 로마자/인덱스 안정키 사용(예: `note_0`…`note_7`)로 시트 join 용이.

## 8. 데이터 구조 영향

- 새 `activityId`: `sound.explore`, `sound.scale`. 새 `taskId`: `explore`, `note_0`…`note_7`. events 신규 타입: `scale_complete`.
- Spec 1의 trials/events 시트 스키마 그대로 사용(컬럼 변화 없음). 분석 시 `tab='sound'`로 필터.

## 9. 검증 방침

- 단일 HTML·무프레임워크 — 브라우저 수동 검증 + Playwright 자동 검증(가능 시).
- 핵심 체크: (a) 1단계 mL 숨김·토글, (b) 골고루 안내·관대한 해제, (c) 2단계 8컵 셀 튜닝·발광·전체 연주, (d) per-note trial 로깅이 시트에 trajectory와 함께 적재, (e) 죽은 코드 제거 후 콘솔 에러 0·앱 정상, (f) 다른 탭 회귀 없음.
- 인라인 스크립트 `node --check` 구문 검사 유지.
